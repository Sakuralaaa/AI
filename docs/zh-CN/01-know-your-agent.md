# 01｜认车：Agent、模型和人的分工

[English](../en/01-know-your-agent.md) · [返回首页](../../README.md)

## 先记住一句话

Agent框架或桌面工作区是车，模型是油，Prompt是目的地；好车、好油和清楚的路线缺一不可，但最终验收的人仍然是你。

## 为什么你会需要它

很多配置问题来自把“车”和“油”混为一谈：换了模型却期待界面和工具变化，换了Agent却以为订阅会自动迁移。把角色分开，就更容易判断应该换模型、换客户端、补上下文，还是收紧权限。

## 四个核心角色

1. **Agent框架（车）：** Codex、Claude Code、PI-Desktop等负责组织会话、工具、文件、执行循环和界面。
2. **模型（油）：** 负责理解、推理和生成。能力更强的模型通常更适合长链路和高风险任务；简单任务未必需要最高规格。
3. **供应商（加油站）：** 负责身份验证、模型访问、计费、限额和可用性。订阅与API是不同产品形态，不能默认互通。
4. **用户（驾驶责任人）：** 决定工作区、目标、允许的操作和验收方法。

## 常用部件

| 概念 | 作用 | 最常见的误区 |
|---|---|---|
| Context | Agent当前能看到的对话、文件和工具结果 | 材料越多越好；实际上无关内容会干扰判断 |
| Token | 模型处理内容的计量单位 | 把Token简单等同于字数或人民币 |
| MCP | 连接外部工具与上下文 | 安装后就安全可靠；实际上仍需审查权限和来源 |
| Skill | 可复用工作流说明 | 当作更强的模型；它提供方法，不增加模型本身能力 |
| Sandbox | 限制本地执行范围 | 遇到问题就关闭；正确做法是找出缺少的最小权限 |
| Approval | 高风险动作前的人工检查点 | 不看内容就连续同意 |

## 跟着做一次：定位问题发生在哪一层

遇到“Agent做不好”时，按顺序问：

1. 目的地是否明确，输出格式和验收标准是否写清？
2. Agent是否拿到了正确文件和背景？
3. 当前模型是否适合任务难度？
4. 工具、MCP或本地软件是否真实可用？
5. 权限是否过小或过大？
6. 供应商是否返回限额、认证或网络错误？

把错误归层，比反复更换提示词有效。

## 我踩过的坑

- 把“模型回答聪明”误当成“它已验证事实”。
- 认为订阅账号天然包含任意客户端的API访问。
- 把CLIProxyAPI简称CPA后，又错误理解成一种`.cpa`文件格式。
- 为了追求便宜频繁换供应商，却没有记录模型映射和结果差异。

## 正常结果

你能用一句话说明：哪个软件在执行、哪个模型在推理、通过哪个供应商访问、有哪些工具和权限、结果由谁检查。

## 验收清单

- [ ] 能区分Agent、模型和供应商。
- [ ] 知道订阅与API不必然互通。
- [ ] 知道MCP和Skill分别解决“连接工具”和“复用方法”。
- [ ] 知道CLIProxyAPI是项目名而不是文件格式。
- [ ] 重要任务保留人工验收。
