# 03｜给车加油：模型、供应商与成本

[English](../en/03-models-and-providers.md) · [返回首页](../../README.md)

## 先记住一句话

不是每段路都要用最贵的油：任务难度、错误代价、速度和预算共同决定模型选择。

## 为什么你会需要它

同一辆Agent可以接入不同模型，模型也可能由不同供应商提供。只看模型名称，忽略供应商限额、上下文、兼容性和计费方式，容易出现“能对话但不能调用工具”“价格便宜却反复返工”等问题。

## 按任务选油

- **轻任务：** 文件分类、格式统一、提取字段、生成初始目录。优先速度和成本。
- **普通任务：** 多文档综合、表格公式、PPT故事线。平衡能力、速度和上下文。
- **复杂或高风险任务：** 研究设计、长链路执行、关键数据解释。优先可靠推理，并增加独立复核。

“强模型”不等于“可信来源”。模型生成的数字、引用和政策结论仍需证据。

## 四种访问方式

1. **官方账号登录：** 最适合先体验产品；具体额度和功能以账号页面为准。
2. **官方API：** 按服务商规则计费，便于程序化和兼容客户端接入。
3. **第三方API：** 配置方便，但要额外评估数据流向、日志、价格和持续运营。
4. **本地模型：** 数据控制更直接，但需要硬件、模型管理和效果评估。

订阅与API是不同产品形态。不要因为能登录网页或桌面应用，就假定任意兼容客户端都有API额度。

## 油耗：怎样控制上下文和Token

- 只提供与当前任务有关的材料。
- 长项目用README、任务简报和交接文件保存稳定背景。
- 让Agent先读目录索引，再按需打开文件。
- 任务完成后开始新会话，不要永久携带无关历史。
- 记录失败重试和返工成本；便宜模型多次返工可能更贵。

## 跟着做一次：建立任务分级表

在成本模板中记录三类任务：任务名称、输入规模、错误代价、候选模型、实际耗时、是否返工和最终成本。运行几次后再形成自己的规则，不照搬他人的“最佳模型榜”。

## 支付与订阅边界

地区可用性、支付方式、汇率、税费和自动续费都可能变化。优先使用服务商公开支持的渠道；本仓库不提供账号共享、来源不明的Key、加密货币入金、虚拟卡绕行或地区限制规避步骤。

## 我踩过的坑

- 只比较单价，不记录返工和人工复核时间。
- 把不同供应商的同名模型当成完全相同的服务体验。
- 把真实Key粘到截图、Issue或示例配置。
- 在敏感数据项目中临时切换未知第三方供应商。

## 正常结果与验收

- [ ] 能说明当前使用的是哪种访问方式。
- [ ] 知道数据会发送给谁、按什么方式计费。
- [ ] 任务按难度和错误代价分级。
- [ ] 任何示例都不含真实凭证。
- [ ] 重要结果不因模型更强而免除复核。
