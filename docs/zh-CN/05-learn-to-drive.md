# 05｜学会开车：工作区、任务、计划与验收

[English](../en/05-learn-to-drive.md) · [返回首页](../../README.md)

## 先记住一句话

一个可靠任务至少说清目标、材料、输出、限制和“什么叫完成”；复杂任务先规划，小步执行，每一步都能检查和撤回。

## 建立干净的工作区

建议把一个任务放在一个独立目录中：

```text
project/
├─ input/       # 原始材料，尽量只读
├─ work/        # 中间文件
├─ output/      # 可交付成果
├─ README.md    # 项目目标与说明
└─ HANDOFF.md   # 当前进度和下一步
```

不要把“桌面”“下载”“整个文档库”直接当工作区。原始材料和输出分开，能显著降低覆盖风险。

## 说清目的地

使用[任务简报模板](../../templates/zh-CN/task-brief.md)：

```text
目标：把三份访谈摘要整理成一份汇报材料。
背景：读者没有参与访谈，需要先理解共同主题。
输入：input/中的三份已脱敏文档。
输出：output/summary.md和output/briefing-outline.md。
限制：不改input；不虚构受访者观点；不使用外部来源。
完成标准：每个主题都能定位到原文，矛盾观点单独列出。
```

这比“帮我总结一下”更长，却能减少多轮返工。

## 什么时候先Plan

任务涉及多个文件、重要数据、不可逆操作或你自己也没想清楚时，先使用Plan模式或明确要求“只调查和提问，不修改”。让Agent说明：

- 已知与未知。
- 预计修改的文件。
- 每一步的输出。
- 风险、依赖和失败后的恢复方式。
- 需要你决定的取舍。

简单、可逆、范围清楚的任务不必为了形式写长计划。

## 执行中的交通规则

1. **先盘点：** 确认文件、格式和数量。
2. **先样例：** 批量操作前先处理一份。
3. **分批执行：** 每批都留下可读结果。
4. **保留原件：** 输出到新目录，除非明确批准覆盖。
5. **用证据汇报：** 说明生成了哪些文件、检查了什么、哪些没有验证。

## 项目怎样“记住”你

- `README.md`：稳定的项目背景、目录和目标。
- `AGENTS.md`：Agent长期遵守的工作约定，例如禁止改原始数据、使用何种Python路径、如何验收。
- `HANDOFF.md`：本轮完成内容、未决问题和下一步。
- 当前Prompt：只放本次任务特有的要求。

OpenAI文档说明，Codex会按全局到项目再到子目录的顺序读取 `AGENTS.md`，更具体的说明优先。文件应短而准确，不要堆积互相矛盾的规则。

## 我踩过的坑

- 在Prompt里混入五个不同目标，最后每个都只完成一半。
- 只写想要的形式，不写事实来源和验收方法。
- 让Agent自己判断是否正确，却不给可计算或可对照的标准。
- 把临时要求永久写进AGENTS.md，影响之后所有任务。

## 正常结果与验收

- [ ] 工作区只包含当前任务所需材料。
- [ ] 原始材料和输出分开。
- [ ] 任务简报包含目标、输入、输出、限制和完成标准。
- [ ] 高风险操作前看过计划或预览。
- [ ] 最终汇报列出实际文件与未验证项。
- [ ] 能用版本记录、备份或恢复映射撤回变更。
