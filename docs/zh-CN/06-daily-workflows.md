# 06｜开车办事：文件、文档、表格与PPT

[English](../en/06-daily-workflows.md) · [返回首页](../../README.md)

## 先记住一句话

通用工作流不是“一句话生成成品”，而是“盘点—样例—批量—核验—交付”；每一步都有看得见的中间产物。

## 文件整理

先让Agent生成清单，再决定分类和命名规则。批量改名时要求输出：原路径、新路径、理由、冲突、是否执行。推荐先用[文件操作预演模板](../../templates/zh-CN/file-operation-preview.md)。

安全提示词：

```text
先扫描input目录并生成rename-plan.csv，不要改动文件。
发现同名、无法识别或可能重复的文件时标为REVIEW，不要自行覆盖。
等我确认映射表后再执行；执行后生成rollback.csv。
```

## 文档和资料总结

把输出拆成三层：事实摘录、结构化总结、Agent推断。每条关键结论保留文件名、章节或页码定位；找不到来源时写“未确认”，不要补出一个看似合理的引用。

适合的中间产物包括：材料清单、主题编码表、矛盾观点表、报告目录和待核实问题。先确认这些，再写长文。

## 表格处理

Agent可以帮助统一列名、日期、单位、缺失值标记，合并多表并生成汇总。但验收必须包含：

- 输入输出行数与唯一键数量。
- 重复和未匹配记录。
- 缺失值变化。
- 单位、币种和日期格式。
- 至少5行抽样复算。
- 公式引用范围和汇总口径。

使用[表格核验模板](../../templates/zh-CN/spreadsheet-check.md)，不要只看最终图表是否“好看”。

## PPT制作

先完成[制作简报](../../templates/zh-CN/presentation-brief.md)：受众、时长、目的、必须出现的证据、母版和禁用内容。推荐三阶段：

1. **故事线：** 每页只写标题、核心信息和证据。
2. **内容版：** 放入表格、图形、引用和Speaker Notes。
3. **视觉版：** 检查字体、溢出、遮挡、对齐、色彩和投影可读性。

重要数字必须回到表格源；图片和引用保留出处。生成`.pptx`不代表视觉验收完成。

## 完整办公闭环

共享案例采用：

```text
原始材料 → 主题摘要 → Word/Markdown报告 → CSV任务表 → PPT故事线 → 人工验收
```

见 [examples/office-workflow](../../examples/office-workflow/README.md)。它故意保留中间产物，让你能发现错误发生在哪一步。

## 我踩过的坑

- 直接让Agent移动上千个文件，没有预演或冲突策略。
- 把二手摘要当原始证据引用。
- 合并表格后只核对总行数，没有检查一对多匹配。
- PPT一次生成20页后只看缩略图，没有逐页检查。

## 正常结果与验收

- [ ] 批量文件操作有预览和恢复映射。
- [ ] 文档事实、总结和推断能够区分。
- [ ] 表格完成行数、键、缺失值和抽样复算。
- [ ] PPT先验故事线，再检查内容与视觉。
- [ ] 最终交付物能追溯到输入和中间产物。
