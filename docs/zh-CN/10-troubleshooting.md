# 10｜路边救援：常见故障排查

[English](../en/10-troubleshooting.md) · [返回首页](../../README.md)

## 先记住一句话

一次只排查一层：先确认工作区和官方直连，再检查客户端配置、本地网关、扩展和具体任务。

## 通用诊断顺序

1. 记录预期结果、实际结果和完整错误时间。
2. 确认操作系统、架构、工具版本和安装来源。
3. 用最小无敏感任务复现。
4. 暂时移除新增层，回到最近一次可用状态。
5. 查看对应层的日志，但先脱敏。
6. 每次只改一个变量并记录结果。

## 安装问题

### GitHub Release下载慢或中断

确认打开的是本仓库列出的项目Release，而不是搜索广告或转载站。可重新下载并用`SHA256SUMS.txt`检查文件；哈希不一致就删除损坏文件重下。不要为了提速转向无法核验来源的网盘包。

### MSIX无法安装

常见原因是x64/ARM64不匹配、App Installer缺失、签名异常、AppX部署服务不可用或设备策略禁止侧载。先按[第02章](02-choose-and-install.md)重新核对架构、SHA256、manifest和数字签名。组织策略阻止时联系管理员，不要下载“破解版”或绕过策略。

### 便携版双击没有反应

确认使用的是Windows x64、ZIP已经完整解压、`ChatGPT.exe`与资源文件仍在同一目录，并查看安全软件给出的具体告警。便携版是社区重打包，不要通过关闭全部防护来强行运行；无法确认告警原因时停止使用。

### PowerShell脚本被阻止

先确认脚本来源和必要性，再参考Microsoft的执行策略文档。不要为了一个工具永久关闭全部脚本保护。

## 工作区与权限

- 找不到文件：确认打开的是正确目录，路径是否在允许范围。
- 能读不能写：检查当前权限配置和输出目录。
- Git功能不可用：确认Windows原生Git已安装且重启了应用。
- WSL项目异常：确认Agent运行环境、终端环境和实际文件位置，不要把三者混为一谈。

## CC-Switch与CPA

- 切换不生效：确认目标客户端、配置文件、重启要求和实际Base URL。
- 401/403：优先检查认证范围、过期和系统时间；不要把Key贴到公开求助帖。
- 404：检查Base URL路径和模型映射。
- 连接被拒绝：确认CPA进程、监听地址和端口。
- 端口占用：查明现有进程，不要盲目结束系统服务。
- 出现复杂错误：恢复官方直连；如果官方直连也失败，先解决账号或客户端问题。

## MCP与专业软件

- 安装后看不到服务器：按当前客户端要求保存并重启，再查看MCP列表和日志。
- 工具存在但无法调用：检查服务器进程、工作目录、环境变量和授权范围。
- Stata无法启动：确认可执行文件路径、许可证、版本兼容和是否能独立启动Stata。
- 命令执行却无输出：检查log、输出目录和脚本中的工作目录设置。

## 文档、表格和PPT

- Agent说完成但没有文件：要求给出绝对或工作区相对路径，再在文件系统核对。
- 中文乱码：确认编码、字体和目标软件。
- 表格数字不一致：回到合并键、过滤条件、缺失值和单位，做抽样复算。
- PPT错位：在目标PowerPoint版本中逐页打开，不以生成日志代替视觉检查。

## 我踩过的坑

- 同时升级客户端、CC-Switch、CPA和模型，无法知道谁引入问题。
- 只截最后一行错误，丢掉真正原因。
- 为求助公开完整配置和Token。
- 没有恢复基线，就不断叠加“修复”。

## 验收清单

- [ ] 能在最小任务中复现或确认问题消失。
- [ ] 每次只改变一个变量。
- [ ] 日志和截图已经脱敏。
- [ ] 知道如何回到官方直连或最近可用配置。
- [ ] 修复后重新执行实际验收，而不只看报错消失。
